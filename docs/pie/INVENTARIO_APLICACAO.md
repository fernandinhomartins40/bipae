# Inventário da aplicação — Bipaê (auditoria PIE)

- **Commit inventariado:** `728df79` (branch `main`, árvore com alterações locais não versionadas em `crm.service.ts`, `mail.service.ts`, `pos.tsx`, `connector.spec.ts`, `update.test.ts`, `docker-compose.vps.yml`).
- **Data:** 27/10/2026. **Ambiente:** Windows 11, leitura estática do repositório. **Nenhum teste foi executado nesta etapa**; a execução cabe a outro revisor.
- **Método:** extração das rotas pelos decorators `@Controller/@Get/@Post/@Put/@Patch/@Delete` + `@RequirePermission/@PlatformPermission/@Public/@PublicApi` (inclusive controllers declarados dentro de arquivos `*.service.ts`), leitura do roteador `packages/erp-ui/src/app.tsx` e `packages/erp-ui/src/admin/admin-app.tsx`, das migrações, da fila e dos testes por nome de arquivo e busca de rota/termo.

## 1. Visão geral

**Stack detectada.** Monorepo pnpm + Turborepo, TypeScript estrito. API NestJS sobre Fastify (`apps/api`), PostgreSQL 16 com RLS (PGlite em `apps/api/.data` sem `DATABASE_URL`), Drizzle ORM, 89 migrações SQL em `apps/api/src/db/migrations` (105 tabelas), fila `QUEUE` (`apps/api/src/common/queue.ts`: `MemoryQueue` em dev/teste, `RedisQueue`/BullMQ com `REDIS_URL`). Front React + Vite + Tailwind + Radix. PDV com SQLite local (nativo no Tauri, WASM/OPFS ou IndexedDB no navegador, `packages/local-db`). Desktop e Android com Tauri 2 (Rust + plugin Kotlin). Testes: Vitest (unitários/integração) e Playwright (projetos `web` e `desktop-ui`, `apps/web/playwright.config.ts`).

**Apps.**
- `apps/api` — API REST (≈389 rotas) + rotinas em segundo plano + `admin-cli.ts`/`seed-cli.ts`.
- `apps/web` — casca fina do backoffice + PDV PWA (`/app/...`), importa `@bipae/erp-ui`.
- `apps/desktop` — casca Tauri 2 (Windows/Linux/macOS) + Bipaê Conector; Rust em `src-tauri/src` (`connector.rs`, `db.rs`, `peripherals.rs`); `tauri.android.conf.json` e plugin `src-tauri/plugins/bipae-terminal` (Kotlin) para o **app Android único** (ADR-0017, `.github/workflows/release-android.yml`).
- `apps/site` — landing estática (`src/main.js`), sem testes.
- `kits/pdv-embed` — componente PDV Embed (ADR-0014) com contrato `contract/openapi.yaml`, servidores de referência Node e PHP, `conformance/run.mjs`.

**Pacotes.** `domain` (schemas Zod, permissões, eventos), `fiscal` (motor puro + tabelas oficiais), `pdv-core` (regras do caixa, ESC/POS, balança, contingência), `pdv-ui` (telas do caixa), `erp-ui` (telas da retaguarda e do painel admin), `platform` (ports de periféricos, Conector, TEF, maquininha smart, certificado), `local-db`, `sync`, `promotions`, `danfe`, `ui`.

**Papéis de usuário (tenant)** — `packages/domain/src/permissions.ts`: Dono (`owner`, todas), Gerente (`manager`, todas menos `admin.users/stores/integrations`), Operador de caixa (`cashier`), Vendedor (`seller`, só `pos.order`), Contador (`accountant`, leitura + `finance.read` + `audit.read`); papéis customizáveis (`/roles`). 21 permissões granulares; `sensitive: true` exige auditoria. **Papéis da plataforma** (super admin, ADR-0013): `owner`, `support`, `viewer` (`packages/domain/src/platform.ts`), com login próprio e TOTP (`/admin/auth/*`).

**Tenants.** Multi-tenant por `tenant_id` + RLS; hierarquia tenant → empresa (`companies`) → loja (`stores`) → caixa (`terminals`); `memberships` com lojas permitidas; troca de conta (`/auth/switch-tenant`); `asPlatform()` restrito a `modules/admin`, `maintenance`, `mercadoflow`, `payments`.

**Recursos pagos/planos.** Tabelas `plans`, `tenant_billing`, `plan_invoices`; limites por plano para `companies, stores, terminals, users, products` (`LimitsService.assertCanAdd`). Não há bloqueio de **funcionalidade** por plano (o PRD §8 prevê planos Grátis/Essencial/Profissional/Rede com recursos diferentes): ver INV-SAAS-07. Cobrança dos planos por Pix/boleto/cartão no parceiro (`modules/billing`, `BILLING_*`).

**Dados pessoais tratados.** Usuários (nome, e-mail, hash de senha, segredo TOTP), clientes (CPF/CNPJ, contato, endereço, crédito/crediário, fidelidade, consentimento de marketing — `customers`, `customer_credit_entries`, `loyalty_entries`, `email_campaign_recipients`), fornecedores, CPF na nota (vendas e documentos fiscais), certificados A1 (`company_certificates`, selado), dados bancários/extratos (`bank_transactions`), sessões e IP (`sessions`, `admin_sessions`), trilhas (`audit_log`, `platform_audit_log`). Direitos LGPD: exportação (`GET /account/export`) e exclusão definitiva de contas canceladas (`ACCOUNT_PURGE`).

**Integrações externas.** SEFAZ (NFC-e/NF-e, eventos, DF-e, cadastro — `fiscal/sefaz.transport.ts`, homologação), ADN/Sefin da NFS-e Nacional (`nfse.transport.ts`), PSPs Pix (API Pix do BC + perfis Efí/Sicoob/Itaú/BB/Inter/Santander/Bradesco; Mercado Pago, PagBank, Asaas), boleto Asaas + CNAB 240, Mercado Pago Point (maquininha nuvem), TEF (CliSiTef/PayGo em `packages/platform/src/tef`), maquininhas smart Android (Kotlin), MercadoFlow (ADR-0015), e-mail SMTP (`SMTP_URL`), IA Anthropic (`ai.provider.ts`, `AI_API_KEY`), iFood e marketplaces (`channels`), armazenamento local/S3 (`common/storage.ts`), releases do desktop no GitHub (`DESKTOP_RELEASES_REPO`).

**Tarefas em segundo plano (fila `QUEUE`).** `nfce.emit`, `nfce.cancel`, `nfe.emit`, `nfe.correction`, `nfse.emit`, `nfse.cancel`, `nfse.received.sync`, `dfe.sync`, `mail.send`, `payments:webhook-check`, `CHANNEL_SEND`, `CHANNEL_CATALOG`, `WEBHOOK_SEND`, `BILLING_SWEEP`, e repetitivas de `maintenance` (`SESSIONS_CLEANUP`, `NFCE_SWEEP`, `WEBHOOK_SWEEP`, `DFE_SWEEP`, `ACCOUNT_NOTICES`, `IMAGES_MIGRATE`, `ACCOUNT_PURGE`, `CHANNELS_SWEEP`) e de `mercadoflow` (`mercadoflow.outbox`, `.customer-daily`, `.stock-daily`, `.promotions`).

**Webhooks de entrada (sem login, `@Public`/rota livre).** `POST /integrations/mercadoflow/webhook`, `POST /payments/webhooks/{pix-api/:token[/pix], mercadopago, pagbank, asaas}`, `POST /boletos/webhooks/asaas`, `POST /channels/inbound/:tenantId/:key`, `POST /crm/campaigns/unsubscribe`.

**Legenda de estado (esta fase).** `IMPLEMENTADA, NÃO VERIFICADA` = código + teste identificado, não executado nesta auditoria. `PARCIAL` = há trechos ausentes, "chega em breve" ou "falta configurar". `BLOQUEADA` = depende de item `E*` de `docs/TAREFAS.md`. `NÃO LOCALIZADA` = exigida no PRD e não achada. Nada está marcado como VERIFICADA.

Abreviações das colunas: testes de API em `apps/api/test/`, E2E em `apps/web/e2e/`, telas em `packages/erp-ui/src/pages/` (rota de UI sob `/app/`).
